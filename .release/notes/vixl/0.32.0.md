# Vixl 0.32.0

## Changes

A multi-document automation and hosting release: step 7 of the
[implementation plan](docs/project/implementation-plan.md). Suite rules read values from other documents and hold
budgets; exported files are read back against delivery specs; approved baselines, link impact, a locale check and a
spelling check cover documents that change together. The new `pipelines` plugin runs resumable pipelines, signed
completion webhooks, `vixl watch`, data sync and bulk upgrades, and the `localization` plugin makes localized
variants with right-to-left mirroring. `vixl host` serves workspaces to AI Server Studio and other programs, with a
published API schema, a `studio` AI provider, a container image and a per-user Windows host task. Fonts installed on
the machine work by name. Breaking changes are listed under Upgrading from 0.31.

### Upgrading from 0.31

- **Font names that failed now resolve.** A text layer's `font` that named neither a registered font, a bundled face
  nor a file used to fail with `missing_font`; an installed font of that name is now embedded instead. Set
  `VIXL_SYSTEM_FONTS=off` to keep the old behaviour. Existing documents resolve exactly as before.
- **Approved documents report changes.** Once a document has approval data (`vixl approve`), the standard checks
  include the `approval` check, so a changed page or artboard is a review finding.
- **Offline mode covers more.** `VIXL_OFFLINE=1` now also stops content-pack downloads and refuses to enable
  third-party plugins; `--plugins` with `--offline` is refused.
- **Pipeline run records re-run their check steps once,** because a step's key now covers its suite files and
  `.vixl-checks.json`.

### Checks across documents

- **Suite rules that read another document.** `expected`, a relation's `to` and a hierarchy's `ratio` take
  `{"ref": "master.vixl#layer.field"}` (a layer or canvas field as the master draws it) or
  `{"ref": "master.vixl#suite:rule-id"}` (the same field of a master's rule), so a campaign follows its master's colour
  and type scale. References resolve like link sources inside the workspace and are read-only; a suite holds and a run
  reads at most 8, rule refs nest at most 4 deep and a cycle is refused as `link_cycle`. A missing document, layer or
  rule needs review, never passes. Results record `references: [{path, digest}]`, and `check --all --since-last`
  names a changed master as the cause (`cause: reference`) (#558).
- **Render time and over-resolution budgets.** The `budget` rule adds `max_ppi` (an image placed above that
  resolution, or with over 4x the pixels it needs) and `max_render_ms` with `proxy` (cold and warm proxy render
  times; always an advisory warning to review, in a rule of its own). Its measurements list the five `worst`
  offenders per limit. The opt-in `budget` design check runs the same limits without a suite, at defaults that
  `budget` in `.vixl-checks.json` overrides (#564).
- **Spelling check.** The new `spelling` plugin adds the opt-in `spelling` check: each word of the drawn text (after
  variables, per artboard) that the dictionary does not know is a `review` finding, `code: unknown-word`, with up to
  three `suggestions`. URLs, domains, emails, `@handles`, `#hex` and hashtags, numbers, words with digits and short
  all-capital acronyms are skipped; brand.json `words.allow`, brand `facts` values and `.vixl/dictionary.txt` are
  accepted. English is bundled (a 320 KB list built from SCOWL); other languages are `spelling-<lang>` content packs,
  and without one the check gives a `dictionary-unavailable` review finding, never a pass. The `text` suite rule takes
  `spelling: true`. Plugins declare optional checks with a manifest `checks` list (#554).
- **Allowed brand words.** brand.json `words.allow` lists names the brand spells its own way: `words.forbid` and
  `words.prefer` skip matches inside them (also in a `text` rule with `brand: true`) and the spelling check accepts
  them (#554).
- **Logo variants on approved backgrounds.** brand.json `logo.variants` maps each variant's layers (a glob such as
  `logo-rev*`) to the backgrounds it is approved on (`dark`, `light`, `@palette-role`, `@extra-name` or a colour). The
  brand check samples the background under each logo with the logo hidden and reports a variant on another background
  as a `fix` (`code: logo-variant-background`) (#555).
- **Export checks read the delivered file back.** `vixl check-file FILE --spec NAME` and `check`/`spec` on
  `vixl_export`, batch targets and `Project.export` compare the written file with a delivery spec: PDF page count,
  TrimBox and BleedBox, embedded fonts, colour spaces, total ink and form fields; raster size, dpi, ICC profile, alpha
  and bytes; PowerPoint text frames and native charts; external URLs in HTML and SVG. Specs are data, presets
  (`print-letter-bleed`, `print-a4-bleed`, `instagram-feed`, `web-banner`, `display-ad`, `slides-pptx`, `web-html`)
  or inline fields on top of one. Findings use the check shape (`check: "export"`), the result is `export_check` and
  the export's outcome takes its validation. A campaign's `export_check` records the report per output in
  `production.json` and holds an output that fails it. Verification is read-only. PDF facts come from pypdfium2 when
  it is installed and a byte scan otherwise; ink a byte scan cannot measure needs review. Proof pages and delivery
  packages read file metadata through the same core inspector (#557).
- **Approved baselines.** `vixl approve` (workflow `approve`) records how a document, or every member of a project
  group with `--group`, looks once it is signed off: per page and artboard a render hash and a reference image of at
  most 256 px, who and when, in `NAME.vixl.approval/` or `.vixl-groups/GROUP.approval/` (at most 64 views). The new
  `approval` check runs with the standard checks whenever approval data exists and reports each changed page or
  artboard as a review warning with the changed fraction and a diff image, so `check --all` marks the document
  needs_review. Approving again accepts the change, and `--clear` removes the approval. `group-apply` and
  `replace-across` dry runs and campaign runs list `approved_members_changed`, and proof pages show an approval
  badge (#559).
- **Link impact.** `vixl links impact SOURCE.vixl` (workflow `link-impact`) checks every document that links to a
  changed source, directly or through nested links, on a refreshed copy that is never saved: a source that changed
  size keeps the link's scale, and each copy runs its checks and suites and is diffed with its current render. The
  report lists the dependents that pass, those that fail with their findings and rule results, the changed pixels,
  the dependency tree and any cycles, in the formats of `check --all`. `--apply` saves only the passing dependents,
  through a journal that `group-recover` can roll back (#560).
- **Workspace dependency graph and candidate evaluation for plugins.** `workspace_qa.dependents` reads who depends on
  which link source, `brand.json`, project group, merge data and library suite from each document's state, cached by
  modification time in `.vixl-checks/links-index.json`. `workspace_qa.candidate` evaluates a change on a copy (checks,
  suites and a render diff) and commits only the clean ones through the group journal. Link impact uses both, and
  other plugins can too. Two new plugin hook points: `cli-command` for command-line shorthands and
  `production-report` for keys in a campaign run's report.

### Automation

- **One completion event for durable jobs.** A job that ends (completed, failed, cancelled or needs review) is handed
  once to the plugins' `job-complete` hook with its kind, id, status, outcome and counts, never document content; a
  resumed job reports its next ending. Plugins add durable job kinds through the `job-kind` hook.
- **Pipelines.** A new `pipelines` plugin runs saved steps over many documents: save a pipeline
  (`{version: 1, targets, steps}`) with `resource-save` kind `pipelines` and run it with `pipeline-run`. Each document
  goes through `act`, `check`, `repair`, `export`, `export_check` and `approve` steps, then `proof` and `package` run
  once over what passed. A document whose step fails is held with its findings while the others continue
  (`on_fail: stop` ends the run instead), and each ends `passed`, `held`, `visual-review-needed` or `failed`. The run
  record `.vixl-runs/RUN/run.json` keeps the Vixl version, input digests (document, brand.json, linked documents,
  data files), per-step logs and outputs with SHA-256; running it again reuses every step whose inputs are unchanged,
  so an interrupted run resumes and an edited document re-runs only its own steps. The first call is a dry run that
  lists every planned output. `act` and `repair` change a working copy, never the source, and exports never replace a
  file the run did not write unless the step says `overwrite: true`. The durable job kind `pipeline` runs it through
  `submit` and `work`, and `package` takes a run record as its input (`run`, `vixl package --run`) (#568).
- **Completion webhooks.** `submit`, `pipeline-run` and `check-all` take `notify: {url, secret_env}`, and
  `.vixl/notify.json` sets a workspace default and the `allow` list of hosts that may receive anything. When the work
  ends, Vixl POSTs one event (kind, id, status, outcome state, counts, report path) signed with
  `X-Vixl-Signature: sha256=…` and named by `X-Vixl-Delivery`, through the same address checks as downloads, with 3
  retries and never any document content; nothing is sent with `VIXL_OFFLINE=1`. `check-all` now hands every finished
  run to the `job-complete` hook in the shared event shape, and skips `.vixl-runs` (#579).
- **Sync from a data source.** `data-sync` binds a keyed CSV to a project group, a campaign spec or a merge sheet,
  diffs it against the last snapshot (`.vixl-runs/data/`; rows added, changed and removed) and changes only what the
  changed rows affect: group members get the new values on a checked copy, committed through a journal and
  re-exported; a campaign re-runs with its fingerprints reusing the unchanged variants; a merge sheet merges again.
  Members that fail their checks are held and retried on the next sync. `dry_run` writes nothing (#572).
- **Bulk structure upgrades.** `bulk-upgrade` converts a glob or group of documents with the conversion kit, renames
  and re-roles layers by name pattern (`map`), and can re-apply a layout keeping the copy of its roles (`template`).
  Each upgraded copy is checked next to the original and render-diffed, and a copy that newly fails is held. It is a
  dry run by default; `dry_run: false` publishes through a journal that `group-recover` rolls back (#578).
- **Plugin resource categories.** The `resource-kind` hook lets a plugin add a resource library category (the
  pipelines plugin adds `pipelines`).
- **Watch mode and schedules.** `vixl watch` (config `.vixl/watch.json`, workflow `watch` for a bounded run, `--once`
  for one pass from cron or CI) re-runs work when files change or a schedule comes round. Triggers are `save` (a
  glob or group), `source-change` (a document others link to, through the dependency graph), `brand-change`,
  `data-change` (a CSV a data-sync binding, a merged sheet or a pipeline's `inputs` reads) and `schedule`
  (`every: "24h"` or a daily UTC `at: "06:00"`, fired once per period however long the watch was stopped); each runs
  `check`, `check-all`, `link-impact`, `pipeline` or `data-sync`. It polls modification times each second and
  compares content, so a touched file is not a change (the optional `watchdog` package wakes it early); events wait
  500 ms and repeated ones coalesce; each document has one run at a time. Results go to the check-all history and the
  completion event, so webhooks fire. A pipeline whose run record's digests match its inputs is not run again, and
  exports keep the pipeline's and data-sync's overwrite rules. The state in `.vixl-runs/watch/` lets a restarted
  watch see what changed while it was stopped. This is the scheduling `check --all --since-last` lacked (#569, #577).
- **`vixl pipeline run NAME`.** `[--dry-run | --execute] [--run ID] [--glob GLOB … | --group NAME]` runs a saved
  pipeline from the command line; the exit code is 1 unless the run completed (#568).
- **Pipelines use the shared candidate evaluation and dependency graph.** `data-sync` and `bulk-upgrade` evaluate
  through `workspace_qa.candidate` and hold the documents' locks from evaluation to commit, so a save in between is no
  longer overwritten. `data-sync` bindings are `data` edges of the dependency graph (indexed in
  `.vixl-runs/data/bindings.json`). Graph readers can declare a `stamp(workspace)` so the edge cache notices their own
  inputs.
- **Pipeline fixes.** A run's input digests now include documents reached through nested links, so a change two
  links away re-runs the steps; a `check` step's key includes its suite file, the library suites and
  `.vixl-checks.json`, so editing them re-runs the check instead of reusing a stale pass; and two documents of a run
  (or two data-sync members) can no longer write the same export file: the second is refused and the dry run reports
  the collision. Run keys of `check` steps changed, so the first run after the upgrade re-runs them once.

- **Localization check.** The new `localization` plugin keeps per-locale variable values on a document
  (`locales-set`: `locales: {code: {variable: value}}` plus `source`, `same_ok`, `fonts`, `fit`, `min_size`, `rtl`),
  on a project group (`group-locales`) or in a strings CSV (a key column and one column per locale).
  `vixl check --locales all|de,ja`, the workflow `check` field `locales` and the `locale-check` action check each
  locale on a candidate copy with the design checks and suites, and report a locale x finding `matrix`: overflow,
  missing glyphs (`fonts`), untranslated values, missing keys and line-count changes that break a `hierarchy` rule,
  as JSON or Markdown. Plugins answer such variant checks through the new `check-variants` hook (#565).
- **Localized variants.** `localize` builds one checked variant per locale: derived `<master>.<code>.vixl` documents,
  exports, or a campaign `spec` run per locale. Text fits by policy (`shrink` through `fit-text` down to `min_size`,
  or `flag`), `ar`, `he` and `fa` are mirrored right to left, per-locale fonts go ahead of the `font-fallbacks`, and a
  locale with a missing key or a failing finding is held with its findings and repairs. `localize.json` fingerprints
  each locale, so a re-run rebuilds only the locales that changed (#576, #171).

### Hosting

- **`vixl host` serves many workspaces to a host application.** A new core server for AI Server Studio and other
  programs: a bearer token is always required, on loopback too (`VIXL_HOST_TOKEN`, `--token-env` or
  `--token-file`/`VIXL_HOST_TOKEN_FILE`), and the host refuses to start without one. Routes under `/w/{ws}/` act in
  the folder `ROOT/ws`, named `[a-z0-9_-]{1,64}` and kept inside `--root`; `GET /host/info` reports the version,
  `host_api: 1`, capabilities, limits and the job TTL, and every error answers one shape,
  `{code, message, hint, layer_id?}`. It takes `--offline`, `--bind` and the per-call limit flags, with the
  shared-server defaults (#537).
- **Host documents have ids, revisions and safe retries.** `POST /w/{ws}/documents` creates a document with an
  opaque id (`d_1a2b3c4d`) recorded in the workspace's index; `import` takes a `.vixl` file under the archive
  budgets, and `GET` returns its state with layer bounds, `blob` its bytes. Operations, raw-byte assets, SVG and PDF
  artwork and `DELETE` wrap the `Session` methods. Each change raises a revision that every answer carries, and
  `if_revision` makes a change conditional (`409 revision_conflict`). A `request_id` makes a retry return the first
  answer, using the same request log as MCP, now `vixl.idempotency` (#538).
- **Host compose, preview and check.** `POST /w/{ws}/documents/{id}/compose` builds a piece in one call and
  replaces the document with it; `preview` takes `page` (or `all` for a contact sheet), `region`, `max_px` and
  `max_bytes` with the MCP preview's size stepping; `check` answers findings as
  `{rule, severity, action, message, layer_id, page}` with `outcome` and `passed`. All three are limited like the
  REST routes (#539).
- **Host exports are jobs with progress.** `POST /w/{ws}/documents/{id}/exports` always answers a job id after
  the page and megapixel preflight; `GET /jobs/{id}` reports a progress fraction that never goes back,
  `/download` returns the file until the job TTL passes (then `410 expired`, and a sweeper deletes it), and
  `/events` streams progress and one `job-complete` event in the shape durable jobs send, which also reaches the
  plugins' `job-complete` hook (#540).
- **Host catalogs and a `studio` tool profile.** `GET /catalog/{kind}` serves the `vixl catalog export` sections,
  the brief guide, the capability matrix (now with a Host column) and operation field schemas;
  `GET /catalog/tools?profile=studio` lists 12 tools in the host's terms, kept in `vixl.guidance.TOOL_PROFILES`, with
  input schemas derived from the operation, compose, check and export registries (#541).
- **The host API has a published contract.** `vixl host --schema` (also `GET /host/schema`) prints
  `host-api.schema.json`, with each endpoint's request and response and `host_api: 1`; releases attach it as
  `vixl-host-api.schema.json`, and a test drives every endpoint against it. A change that removes an endpoint or a
  field, or changes its meaning, raises `host_api` and needs a migration note here; additions do not. "Embed Vixl in
  another app" (AGT-30) moves from a days-long T5 project on `vixl serve` to T1 with `vixl host` (#543).
- **Offline mode covers content packs and plugins.** `VIXL_OFFLINE=1` now also stops content-pack downloads (as
  `VIXL_PACK_DOWNLOAD=off` does) and refuses to enable third-party plugins, whose code it cannot bind;
  `--plugins` with `--offline` is refused (#537).
- **Design Profile import and export.** `vixl brand import --design-profile FILE.json` writes brand.json from a
  Design Profile (`schemaVersion: 2`: typography, colours, page, docText) and `vixl brand export --design-profile
  FILE.json` writes the workspace brand as one; both are brand kit workflow actions (`brand-import`, `brand-export`),
  list every path they cannot map under `unmapped` and refuse to overwrite without `overwrite`.
  `vixl.brand.load_brand_or_profile(data)` reads either shape for the host through the new `brand-format` hook (#545).
- **A `studio` AI provider for the host.** `vixl host --provider studio --provider-url URL --provider-token-env ENV`
  sends plan, describe, detect, ocr, generate, segment, upscale and background-remove to an AI Server Studio gateway:
  one `POST URL/v1/<capability>` with the capability, its constraints and inputs, never a model. It is registered in
  the host process only (never providers.json), takes every capability while active and refuses other providers, and
  is the one URL `--offline` lets through. A host request's `X-Call-Context` header is echoed on every gateway call;
  gateway errors answer `provider_refused`, `limit_exceeded` or `provider_error`; provenance is recorded as before.
  `POST /w/{ws}/documents/{id}/ai` runs AI commands through it. Studio has not published a gateway contract, so the
  one in docs/reference/providers.md is Vixl's proposal. Plugins add `vixl host` flags with the new `host-flags`
  hook and read them as `host.options` (#544).
- **An official container image.** `ghcr.io/jxburros/vixl:VERSION` and `VERSION-full` (with ffmpeg) run
  `vixl host --root /data --offline --bind 0.0.0.0` as uid 10001 from `distribution/container/Dockerfile`: the
  published `vixl-engine[server,pdf]`, a `/data` volume, caches on `/tmp` so `--read-only` works, the token from
  `VIXL_HOST_TOKEN` or `VIXL_HOST_TOKEN_FILE`, a `HEALTHCHECK` on `/host/health` that sends it, and every content pack
  fetched and checked at build time. `.github/workflows/container.yml` builds, smoke-tests read-only and pushes both
  on a version tag; the Dockerfile's `ARG VERSION` joins the version-sync list (#546).
- **Windows: Vixl host for AI Server Studio.** The installer's optional task registers a per-user Scheduled Task
  (`Vixl host`, at logon, restart on failure, no admin rights) running `vixl host --root %LOCALAPPDATA%\Vixl\host
  --offline --bind 127.0.0.1` with a generated 32-byte token, and writes `%LOCALAPPDATA%\Vixl\host.json`
  `{url, token_file}`, both readable by the user only. The updater restarts the task after it activates a version
  when host.json exists; the uninstaller removes the task and host.json. A machine-wide service is not built, and
  which of the two Studio detects is not confirmed yet (#547).
- **Host workspace brand.** `PUT /w/{ws}/brand` takes brand.json or a Design Profile (`schemaVersion: 2`), validates
  it and writes `ROOT/ws/brand.json`, answering the kit, its summary, `source`, the profile paths it could not map
  (`unmapped`) and a `digest`; `?if_digest=` makes the write conditional (`409 revision_conflict`). `GET /w/{ws}/brand`
  reads it back. New documents in the workspace use the brand; existing ones are unchanged (#545).

### Fixes

- **A brand with `palette.extra` no longer breaks `vixl new`, `roll --apply`, `layout apply` or templates.** `vixl new`
  failed with `unhashable type: 'dict'` and the others with `colors keys are …`: rolls and layouts take the brand's
  palette roles, not the table of extra colours.

### Fonts

- **Fonts installed on this machine work by name.** A text layer's `font` (and `display_font`, a rich-text span's
  `font`) takes any installed font by family (`"Georgia"`), family and style (`"Georgia Bold Italic"`,
  `"Inter SemiBold"`), full or PostScript name (`"Georgia-BoldItalic"`) or file name, ignoring case and spaces; a
  missing style takes the nearest weight with the same slope, as CSS does. Vixl finds the fonts other programs see:
  fontconfig on Linux and BSD (the font folders without it), the font registry and folders on Windows, the font
  folders on macOS, plus `VIXL_FONT_DIRS`. The face is embedded and registered as `family-weight[-italic]`, so the
  document renders and exports on machines without it; a collection member is extracted and a variable instance made
  static. Bold and italic rich-text spans embed the family's real bold and italic. Registered names, roles, bundled
  faces and paths resolve as before, text without a font keeps the bundled proofing face, and only names that failed
  now resolve. The result lists each face under `installed_fonts` with its embedding permission; a `restricted` or
  `preview-print` face warns, and is refused through MCP and REST. Unknown names suggest close installed families.
  `VIXL_SYSTEM_FONTS=off` turns it off, `extra` keeps only `VIXL_FONT_DIRS`. The test suite runs with it off.
- **Listing installed fonts.** `vixl font system [QUERY] [--styles] [--limit N] [--refresh]`,
  `vixl_reference('fonts', view='installed', query=…)`, `GET /typefaces/installed` (no file paths) and
  `vixl.system_fonts.families()` / `lookup()` list each installed family's styles with weight, slope, PostScript name,
  file, collection index, embedding permission and licence; catalog rows of installed families carry
  `installed: true`. Faces are indexed once per process from an on-disk index keyed by file size and modification time
  (`VIXL_SYSTEM_FONT_INDEX`), bounded to 6,000 files of at most 64 MB.
- **Script fallbacks and SVG import use installed faces.** CJK, Devanagari and Thai text also draws from an installed
  catalog Noto face (or Noto Sans CJK and Source Han Sans under their system names), and an SVG import that cannot
  find a font again takes an installed face of that family before falling back to the proofing face.

# Vixl 0.36.0

## Changes

Security hardening from the 2026-11-09 scan (roadmap stage 12), every built-in layout passing its own checks,
cut-paper, motion and four-legged characters (stage 6), chart editing by data (stage 7), interchange, colour fonts and
tagged PDF (stage 9), and the agent-experience reports of late October.

### Security

- **REST imports and uploads are heavy calls.** REST `/import`, `/assets` and `/fonts` and the `vixl host` asset
  upload run on the bounded worker pool, count against `--max-concurrent`, answer 202 with a job after the call
  timeout and are cancelled at the hard timeout. They previously ran in the generic thread pool with none of these
  (#821).
- **MCP renders count against `--max-concurrent`.** `vixl_render` cannot become a job, so over the cap it waits for
  a free slot for up to the inline time and is then refused with a retryable `limit_exceeded` (#828).
- **The MCP server bounds the calls it holds:** `VIXL_MCP_WORKERS` running plus `VIXL_MCP_QUEUE` (default 64)
  waiting, never more than the 100 jobs it remembers. The next call is refused with a retryable `limit_exceeded`
  (`limit: max_queue`), the job store refuses a job rather than grow past its maximum, and `vixl_job` polls run on
  their own bounded pool (#823).
- **`vixl mcp --http` limits each request body** (the asset limit as base64 plus 1 MiB by default, or
  `VIXL_MCP_MAX_BODY_BYTES`) and answers 413 `resource_limit` before the MCP SDK reads a larger one (#826).
- **Durable workflow queues are bounded** (#824). A queue runs one worker process: `start`, or `submit` with
  `start`, launches nothing while one is alive and answers `already_running`, and a second `workflow worker` exits.
  `submit` is refused with `limit_exceeded` past 64 unfinished jobs (`limit: max_pending_jobs`,
  `VIXL_QUEUE_MAX_JOBS`) or 4096 MB of queue storage (`limit: max_queue_mb`, `VIXL_QUEUE_MAX_MB`). Completed, failed
  and cancelled jobs are deleted 7 days after they ended (`VIXL_QUEUE_RETENTION_DAYS`); published outputs stay and
  `needs_review` jobs are kept. `0` turns a quota off.
- **REST resource routes stay in the workspace** (#820). `GET /resources/{kind}`, `GET`/`POST
  /resources/{kind}/{name}` on the one-document REST app read and save the workspace library (`.vixl-resources.json`
  beside the document) instead of the user library (`VIXL_RESOURCES`, `~/.config/vixl/resources.json`), which
  services now only inherit read-only. Breaking: resources saved through REST before this went to the user library;
  they are still inherited.
- **Link status and errors no longer show server paths** (#829). The `path` of each link (`links`, `inspect`, the
  `links` check), the paths a missing link was looked for, and the `chain` of a link cycle are relative to the
  workspace (or to the document's folder, or the file name alone outside both). Breaking: `path` was absolute; only
  a project with `allow_linked` still reports the absolute path of a file outside the workspace and the document's
  folder.
- **Editable SVG import works within cumulative budgets** (#818): at most 4,096 stylesheet rules, indexed by ID,
  class and type with the rule comparisons capped; each embedded image is decoded and stored once however many
  `<use>` references draw it; and the embedded images plus the canvas-sized raster fallbacks of `svg_mode: "auto"`
  share `Limits.max_load_pixels` (still at most 64 fallbacks). Over a budget the import fails with `resource_limit`
  before the work is done.
- **Importing Vixl's own SVG checks the font limit before any lookup** (#819) (`max_load_fonts`, 64) and makes one
  Google Fonts lookup per style. **Default change:** `install_fonts` is now off unless given for MCP, REST, Host and
  Python imports; only the `vixl import` command installs fonts for SVG by default (`--no-install-fonts` turns it
  off). Pass `install_fonts: true` to let a served import download a Google font the cache lacks.
- **Editable PDF import bounds what pdfium reports before acting on it** (#822): string sizes (1 MiB, 8 MiB of text
  per import) before allocating, path and clip segments (100,000 per path, 2 million per import) before iterating,
  forms at most 16 deep with one 20,000-object budget per import, and decoded images plus full-page fallback renders
  within `Limits.max_load_pixels`. Over a budget the import fails with `resource_limit`.
- **Network responses can no longer allocate past their caps before they are refused** (#827). One reader
  (`vixl.fetch.read_bounded`) now takes every HTTP body Vixl reads (URL imports, Google Fonts, AI provider and
  studio gateway answers, the Figma API): it refuses an oversized `Content-Length` first, takes the body 64 KiB at a
  time and checks each piece before it joins the buffer, and decodes gzip and deflate itself with a bounded output,
  so a compressed body is refused at the cap instead of after it has expanded. Requests ask for `gzip, deflate`
  only; an answer in another `Content-Encoding` fails as a download error. The Figma client streams its answers
  instead of reading them whole before the 256 MiB check.
- **A URL download's 120 s limit covers the whole fetch** (#830). One deadline is set at the start, checked before
  every redirect hop and between reads of the body, and each hop's timeout is the smaller of 30 s and the time left
  (before, every redirect got a fresh 30 s). A completion webhook's answer is read undecoded, at most 64 KiB, and
  reading stops 30 s after the delivery began, so a receiver that trickles its answer keeps its status but not the
  connection.
- **A regular expression from a caller can no longer hold a service past its hard timeout** (#825). On a service
  (any MCP call, any limited REST or Host call, every `vixl serve`/`view`/`mcp`/`host` process, or
  `VIXL_SAFE_REGEX=1`) the patterns of selectors (`name_regex`, `text_regex`), text suites (`pattern`, `forbid`),
  copy facts, brand.json `placeholders` and `replace-across` run on Python's `re` only when Vixl can bound their
  backtracking for the text they will read; ordinary patterns pass and behave as before. A pattern with no bound
  (back-references, `(a+)+`, `(a|ab)+`, `(a?)*`) is refused with the reason, a selector pattern too slow for its
  2,000-character window is refused when sent, and text longer than a pattern's limit fails with `resource_limit`.
  The new optional extra `re2` (`pip install 'vixl-engine[re2]'`, google-re2) lifts those refusals: RE2 then runs
  what `re` cannot bound, in linear time. Each match is a cancellation checkpoint, and `GET /limits` reports the
  mode under `caller_regex`. The CLI and Python API keep plain `re`; `VIXL_SAFE_REGEX=0` turns the bound off on a
  trusted server.

### Added

- **Sprites drawn inside Vixl.** `pixel-draw` gains `tool: "ellipse"` (a filled ellipse inscribed in its `x, y,
  width, height` box, symmetric at any size) and `only` (palette symbols a tool may overwrite, to shade just the
  cells that are already hair). The new `pixel-transform` mirrors a sprite's stored rows (`flip:
  horizontal|vertical|both`) or shifts them by whole cells (`shift: [dx, dy]`, with `wrap` or `fill`), on one layer
  or `targets`: `duplicate` plus `pixel-transform` makes the right-facing frame or the walk-cycle bob, and shading
  keeps its light (#791).
- **Sprite sheets as a grid.** `sprite-sheet` declares a document as rows of facings and columns of frames with a
  fixed cell (`{cell: [32, 48], rows: ["down", "left", "right", "up"], columns: 4, clips}`) and fits the canvas to
  it; `pixel-art` and `move` take `cell: ["left", 2]` instead of x and y, and a sprite has to fit its cell, so an
  outline never reaches the next frame. `export-animation` with `format: "sheet"` (`vixl_export(kind="animation")`)
  then writes the sheet and its clips (name, row, loop, frame rectangles, durations) as neutral JSON, or Aseprite
  frames and frameTags with `metadata: "aseprite"`; a clip without a row stands for one per row (`walk-down`,
  `idle-left`). Sheets of saved frames are unchanged (#792).
- **Crisp enlargements of pixel-art images.** `scale` and `resize` take `sampling` (`smooth`, or `nearest` to
  enlarge an image layer pixel by pixel), and `add` and the `import-image` step take it with a `scale` factor
  (`{"type": "import-image", "path": "hero.png", "scale": 3, "sampling": "nearest"}`; CLI `--scale`, `--sampling`).
  The choice is stored on the layer, so later resizes and rotations, previews and every export keep the pixels
  crisp: PNG, SVG (`image-rendering: pixelated`), PDF and PPTX (#793).
- **Chart marks by data.** Any operation's `target` (or an entry of `targets`) can name a chart's parts by series
  and category: `{"chart": "sales", "series": "Tea", "category": "Dec", "part": "value"}`. Generated layers now
  record what they stand for (`chart_mark`) and are matched by it on redraw, so each series and category keeps its
  layer ID through reorders and removed rows. Unknown names fail with the valid ones. New plugin hook
  `target-resolver` (#778).
- **`chart-emphasis`.** Keeps chosen categories (optionally one series) in colour, mutes the rest (`fade` with
  `opacity`, or `desaturate`) and sets a callout with `${value}` beside each focus mark. Stored with the chart, so
  `chart-data` keeps it; `focus: []` restores the chart. Native point colours in PPTX. `check --checks color_vision`
  reports focus and muted marks that look alike or muted marks that vanish (#779).
- **Emoji packs for WhatsApp, Telegram, Twitch and iMessage, animated packs, and several destinations in one call.**
  `vixl emoji export` / `emoji-export` / `export_pack` gain the destinations `whatsapp` (3–30 stickers as 512×512
  WebP under 100 KB, a 96×96 tray icon and `contents.json`), `telegram` (512 px PNG stickers), `telegram-emoji` (100
  px custom emoji), `telegram-animated` (one vector `.tgs` per emoji, with the TGS limits and no raster fallbacks),
  `twitch` (PNG at 28, 56 and 112 px, letters-and-digits names) and `imessage` (a PNG/APNG sticker folder at 300,
  408 or 618 px with Xcode steps; no Xcode project). `destination` takes a list (`--destination slack discord
  whatsapp`): each destination gets its own `NAME-DESTINATION.zip`, every emoji is drawn once per size, and nothing
  is written when any destination's rule fails. `animated` (`--animated`) exports emojis whose VIXL master has a
  timeline as GIF, WebP or APNG inside the destination's byte, frame and duration budgets, stepping colours or
  quality and then the frame rate down, and refuses what cannot fit. Every platform limit is data in
  `emojis.DESTINATIONS` with its source page and the day it was read; `emoji-requirements` takes the same
  destination list, `animated` and `size` and reports pack-level findings. `emoji-pack-install` accepts the new
  packs (#722).
- **Coordinates on previews.** `vixl_render(rulers=true)` draws a grid labelled in document pixels and `bounds=true`
  (or layer names) outlines layers with `name x,y WxH`; both keep absolute coordinates under `region`, work in
  `vixl_apply` previews and `vixl render --show-rulers --show-bounds`, and never reach an export. The vector-paths
  guide builds a multi-part object from coordinates (#802).
- **Layer styles inside the silhouette: `inner-shadow`, `inner-glow` and `bevel`** (#751). `layer-style` takes three
  new names that follow the layer's alpha and never draw outside it: `inner-shadow` {color, dx, dy, blur, opacity},
  `inner-glow` {color, blur, opacity} and `bevel` {angle, size, highlight, shadow, opacity}, which lights the edge
  facing the light and shades the far one in one call. Their directions are the canvas's, so the light stays put
  when a layer turns. SVG writes them as native filters with the same steps as the renderer; PDF embeds the styled
  layer as an image (`raster_fallbacks`); PPTX writes a lone inner shadow on an unturned shape as PowerPoint's own
  (`native_effects` in the report, with a warning that LibreOffice Impress does not draw it) and pictures the rest.
  `cut-paper` takes `edge_light: {angle}` to bevel every piece.
- **Hand-lettered work stays live text** (#728). `hand_set: {seed, unit, rise, rotate, scale, tracking}` on `text`,
  `text-set` or `rich-text` gives every word (or letter) its own seeded baseline lift, turn, size and spacing when
  the layer is drawn, so the stored text stays editable and the contrast, size, bounds and font checks still read
  it; a word keeps its numbers when others change. Rich-text spans take `rise`, `rotate` and `scale` (`[late]{rise=8
  rotate=-6 scale=1.3}`, `text-style`). PNG, SVG and PDF draw the same glyphs, and PDF keeps real text; PPTX draws
  such a layer as a picture described by its text. `irregular` still refuses text and now points at `hand_set`.
- **Combine motion on one property.** `keyframes` `mode: "add"` writes a named additive layer (`additive`) that is
  stored on the track and summed at render, in every timeline export (GIF, video, Lottie, frames) and in the motion
  check. `sample.blend` hands a wave over to one-off poses and back in phase, `keyframes` with `blend` does the same
  to keys already on a track, and `sample` takes a list of segments joined without a step (#750).
- **Four-legged characters.** `character` with `species` (horse, unicorn, dog, cat) or `plan: "quadruped"` draws a
  side-view animal, or binds your own artwork with `parts`, and rigs it at shoulder, hip, knee and hock.
  `character-cycle` gains `trot`, `gallop` and `jump` (with quadruped `walk` and `idle`), written as editable joint
  keys with the feet landing in sequence; a jump blends into the gait under it and adds its height on top. The
  `character` check reports `joint-detached` (#749).
- **Colour fonts in text.** A text layer set in a colour font file (COLR v0 and v1, OpenType-SVG, CBDT/CBLC such as
  Noto Color Emoji, sbix such as Apple Color Emoji) now draws its colour glyphs instead of being refused: on the
  baseline, counted in `ink_bounds` and the overflow checks, in plain and rich text, fitted text, text on a path and
  `text-animate`. SVG writes COLR and SVG glyphs as vector and embeds bitmap strikes as images listed under
  `raster_fallbacks`; PDF writes flat COLR v0 layers as vector paths and keeps other formats as a reported image of
  the layer; PowerPoint gets a reported picture. Bitmap-only colour fonts can be imported and installed ones are
  listed. The VIXL Line library stays the default for emoji; `emoji-mode` `font` draws them from the font, and
  joined sequences now keep their joiners there. A colour glyph takes no stroke, bold or slant and cannot be warped
  (#721). Hand-set text (`hand_set`, span `rise`/`rotate`) lifts and turns colour glyphs like outline ones.
- **Detect objects in existing documents** (#383). `vixl_apply(workflow='object-detect')` (CLI `vixl object detect
  [--apply]`) proposes which undeclared layers form which objects and of what kind: organic groups by preset,
  characters, groups and loose layers named after a kind (`My Guitar`, `guitar-body`), and part-named layers whose
  ink touches (`head`, `body`, `ear-l`, `whiskers` is a cat; generic parts give the class). Each proposal is
  `{source, layers, proposed_kind, confidence, reasons, parts, batch}` with ordinary `group` and `object`
  operations. It is a dry run by default; `apply: true` applies the proposals at or above `min_confidence` (0.7) as
  one undo step and returns the object check. A grouping that would change the picture is marked `changes_render`
  and never applied. Charts, tables, diagrams, containers, repeats, text and frames get no proposal. Offline unless
  `provider` is passed, which adds a provider's labels for raster images as low-confidence candidates. New built-in
  plugin `object_detect`; `parts.components` is now public.
- **Tagged PDF.** `export --tagged` (`tagged=True`; MCP and REST `tagged: true`) writes a structure tree for screen
  readers and accessibility checkers: `Document` > `Sect` per page > `H1`–`H3` (from text stages), `P`, `Figure`
  with the layer's alt text and `Form` for fillable fields, in the page's `reading_order`, with a `ParentTree`,
  `/MarkInfo` and `/Lang`; decorative layers, undescribed shapes and the page background are artifacts. Off by
  default: an untagged export is byte-identical. A delivery spec can require it (`spec: {"tagged": true}`). No
  PDF/UA identifier is written (#719).
- **A printer's template as guides.** Guides take a `role` (`safe`, `keep-out`, `fold`, `trim`, `bleed`) and `rect:
  [x, y, w, h]` for a closed outline. The `safe_area` check reads them: ink (strokes and effects included) outside
  the safe outline of its panel (`outside-safe-guide`, `outside-safe-guides`), inside a keep-out such as a barcode
  notch (`keep-out`), and text across a fold (`crosses-fold`), each naming the guide and the layer. A document with
  `safe` guides is judged by them instead of the size preset's inset (#727).
- **`guides-import`** (workflow and `vixl guides-import`) reads a template PNG or PSD: map each line colour to a
  role and its dashed or solid lines become role guides on whole pixels, closed outlines where lines meet (a notched
  safe area stays one guide); a PSD can also give named guide layers and its ruler guides. `save` keeps them as a
  **guide set** (`guide-sets` resource); the new `guide-set` operation and `guide-set-save` workflow reuse it on
  other documents (#727).
- **PSD export can keep plain text editable (opt-in).** `psd_text: "editable"` (CLI `--psd-text editable`) writes a
  text layer with one font, size and colour (point text or a text box, rotated at most) as a Photoshop type layer:
  its pixels plus a type-tool block with the text, PostScript font name, size, colour, tracking, leading and
  alignment, listed under `editable_text`. Other text stays pixels. The default export is unchanged pixel layers
  with no type-tool block, because the type layers are not yet confirmed in Photoshop or Photopea. `text_as_pixels`
  now gives `{layer, id, reason}` for each text layer (breaking: it was a list of names) (#514).
- **Layered PSD import.** `vixl import design.psd`, an `import-document` step and `POST /import?format=psd` read
  8-bit RGB PSD files (raw or RLE) with a bounded built-in reader: pixel layers, groups, order, names, visibility,
  opacity, blend modes and layer masks; type layers arrive as images with their text listed; `not_applied` lists
  adjustment layers, effects, clipping and other features the pixels do not carry; `svg_mode: "appearance"` imports
  the merged image. Malformed, unsupported and oversized files fail with `invalid_psd`, `unsupported_psd` or
  `resource_limit` before large allocations. New plugin `psd_import` (#514).

### Changed

- **Every built-in layout passes its own checks.** The layout-quality gate has no exceptions left: all 204 layout x
  size pairs pass at three seeds. The fixes, by layout: `rule-of-thirds` on a square or upright canvas shares the
  height between the copy and the focal point: the copy never crosses the focal point, which sits on the thirds line
  where the gap to the copy allows and gives up size before the headline does, so no band between them or at an edge
  reads as dead (#803). `golden-section` stacked on a square or upright canvas fills its minor section: short copy
  grows (up to 1.6 times), the picture takes the spare height or gives up height for long copy, and on a story the
  section is a `@surface` panel over the safe inset (#804). `z-pattern` shares the height between the headline and
  the body: the headline grows toward the free height, the body's box is sized to its copy (and takes the width
  beside the button on a shallow banner) and lifts off the bottom row on a tall canvas, so no hole is left between
  them and the body no longer overflows on `web-banner` (#805). `split-screen` stacks the picture over the copy on a
  square whose column would cap the headline under its step, always sets a stacked copy zone on a `@surface` panel
  (which owns a story's safe inset), and lets the picture give up height before any type shrinks, so minor text
  keeps its minimum size (#806). `banner` and `photo-caption` keep the headline a step (1.6 times) over the subtitle
  where the use-size minimum would set both at one size (`x-header`, `email-banner`, `ebook-cover`), so the headline
  is the focal point (#807). `editorial-grid` on an upright page gives the spare height of short copy to the
  picture, so the column ends on the bottom margin instead of leaving the foot of the page empty (#808).
- **Layouts: centred lines share one axis.** A body line narrowed to its measure stays centred (or right-set) in its
  column in every layout (`big-number`, `price-list`, `framed`), and the `emblem` initials and tagline are recorded
  as centred on the badge (#809).
- **`minimal-mark` keeps its hierarchy step.** The headline is at least 1.6 times the body on scales with a small
  ratio and on covers (#810).
- **`slide-content` spreads a short list.** The points share the free height in even steps down to the footer
  instead of leaving a band above it (#811).
- **`asymmetric-balance` and `hero-statement` settle their copy.** The copy opposite the counterweight, and the copy
  inside an outline accent, no longer leave a top band that dwarfs the bottom margin (#812).
- **`photo-caption` on a story.** The scrim opens above the copy to balance the story's bottom inset (#813).
- **`business-card` settles between the margins** when the contact lines follow the role; the stale
  `typographic-poster` cover exception is removed (#814).
- **A text box in one operation.** `text` takes `width` and `height`: the text box in the same operation, as
  `text-layout` sets it (the text wraps and `align` works inside it), reported under `normalized`; `vixl text add`
  takes `--width`/`--height`. A centred label in a column is one operation (#794).
- **A first-step guide.** `vixl guide --brief BRIEF` (`vixl_reference(BRIEF, detail="brief")`) prints only the first
  step, the operations to reach for and how to get the whole guide. The interface reference, troubleshooting and the
  skill say how to run the CLI when `vixl` is not on PATH and why the `vixl_*` tools can appear late (#797).
- **Shapes by kind in the operations reference.** `vixl_reference('operations')` opens with shapes by kind (the kind
  is a field, with worked examples), the path defaults (`x`/`y` 0) and when to use `pen` instead of `shape` with
  `path`; `fill` or `color` sent as an operation type explains that they are fields. The `stroke_width` advisory no
  longer fires when editing a shape that already has a stroke colour (#798).
- **Intentional artwork stops asking for review.** `role: "decoration"` or `"background"` on `shape`, `pen`,
  `solid`, `gradient` and `add` marks a layer that may leave the safe area (as `layer-intent` does); the finding
  becomes informational and the review message names the field. An export now takes the verdict of the last design
  check when it is of the same revision and covered the whole document with the default checks (`validated`,
  `needs_review` or `validation_failed`); partial or stale checks and exports of a variant stay `unvalidated`
  (#799).
- **Shorter answers.** `vixl_reference('sizes')` without `name` or `category` is a compact index (about 5 KB instead
  of 21 KB) and `name` matches several words or a pixel size. `vixl_apply(detail="ack")` names the changed layers
  (`changed_layers`) and, with `check`, the findings that ask for a fix or a review. MCP check results no longer
  repeat the default check list or a `summary` equal to `top`, and `last_check` on exports and previews is the
  verdict, counts and open findings only (#800).
- **A local server says where it works.** A local `vixl mcp` (stdio) names its workspace folder in `vixl_document`
  create, open and list results and in `vixl_apply(create=…)`, and adds a `git` note when the repository ignores a
  new document, so a source that would never be committed is noticed at once; network servers still keep the
  location private. Trial documents made in the Vixl repository go under the ignored `scratch/` folder (#801).
- **Textures follow the layer they texture** (#747). `pattern-fill` and `drawn-texture` now add an effect to the
  target layer instead of a sibling raster layer, so the texture moves, turns and scales with the layer under its
  own animation and adds no layer. `name` labels the effect for `effect-set`/`effect-move`/`effect-remove`,
  `opacity` is its amount (animate `effect:<id>`), and `blend` is new. Breaking: the texture is no longer a layer;
  pass `layer: true` for the old separate overlay. Vector exports draw a textured layer as an image.
- **Cut-paper frames reuse the drawn pieces on each new hold** (#754). Stop-motion jitter moved every piece by a
  fraction of a pixel, which missed the raster cache, so each new hold drew every piece again. Jitter is now an
  offset applied when a piece is composited (one sub-pixel resampling of the drawn piece). A 300-layer scene at
  960x540 went from about 1.5 s to about 0.25 s for a frame that starts a hold (`pytest -m perf` budget). Offsets
  are seeded by name and paper seed, so a rebuilt scene gives the same frames. Path polygons and bounds are
  memoised. `render_at(..., draft=True)` and `draft` on previews place layers on whole pixels for a quicker pose
  check. Intended pixel change: jittered frames differ slightly from before.
- **Motion check accepts seamless scrolls and symmetric turns.** `wrap` (the repeat distance, on `keyframes`,
  `keyframe` and `animate`) and `symmetry` on rotation tracks mark a track as repeating: the loop-seam checks
  compare it modulo that period, `close` leaves it alone and a constant-speed whole repeat is no longer
  `linear-motion`. The `loop-seam` message names the `wrap` or `symmetry` that would make a constant-speed track
  seamless, and `motion` gains a `scroll` recipe (#752).
- **Fewer seam notes.** `loop-seam-speed` is no longer reported for a sampled motion whose seam is no sharper than
  its own keys.

### Fixed

- **Cut-paper grain no longer shows scanlines** (#748). `cut-paper` grain was one random value per pixel row across
  the full width, so large pieces looked like TV scanlines at the recommended `grain`. It is now soft mottling,
  short fibres at random angles and fine tooth, seeded and the same on every frame. New optional fields shape it:
  `grain_scale`, `fibers: {count, length}` and `pattern` (a built-in or `pattern-define` tile as the paper texture).
  Intended render change: every cut-paper layer draws differently.
- **Chart errors name their lists correctly.** Unknown chart category and series errors read "categorys" and
  "seriess".
- **Emoji sequences keep their joiners.** The bidi pass dropped zero-width joiners, so a joined emoji sequence drawn
  from a font came out as separate glyphs.

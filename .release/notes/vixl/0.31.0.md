# Vixl 0.31.0

## Changes

A craft, objects and brand packages release: steps 5 and 6 of the
[implementation plan](docs/project/implementation-plan.md). Type gets small caps, hanging punctuation, accent words
and three finishing containers; the composition check finds flat hierarchy, a single weight, no focal point and an
unused accent, and `variations` shows seeded directions side by side. Rolls draw zero to three accents and weight
their palette by the brief's words, stacks lay out like flexbox and grid, and `adapt-layout` recomposes, crops around
a focal point and tries alternative arrangements. Scenes get fog and nine more motif themes; organic forms and
object scaffolds get the house illustration finish; Noto Sans is the proofing face. Object kinds carry build
knowledge, declared objects are checked against their kind, outlined by policy and scaffolded with `object-plan`.
Brand packs carry images, templates anchor to text lines and compute values, and brands install from one file. Merch
mockups, portable characters, full render lockfiles and deliverable packages complete it. No craft gain is claimed:
the blind re-judge has not run. Breaking changes are listed under Upgrading from 0.30.

### Upgrading from 0.30

- **More review findings by default.** The composition check adds `flat_hierarchy`, `single_weight`, `no_focal` and
  `accent_unused`, and pages with a declared object run the `object` check, whose missing parts and gaps are `fix`
  findings. A document that passed `vixl_check` or the `final` profile can now report findings or fail; waive a
  review finding with a reason, or fix the design.
- **Rolls and briefs pick colours differently.** A roll may draw zero, two or three accents (`@accent-2`,
  `@accent-3`), and a brief's words weight its palette. `locks={accents: 1}` restores one accent; lock the palette
  (`locks={palette: NAME}`) or create the document with `house_style: off` to keep a palette.
- **`adapt-layout` recomposes an unedited layout document.** Pass `recompose: false` (CLI `--no-recompose`) for
  the old proportional scaling.
- **Organic forms and `object-plan` scaffolds get the house illustration finish** in a document with a house
  style. Pass `illustration: "plain"` (or `outline: false`) per form, or create the document with
  `house_style: off`. Under `outline: parts` the default outline width is 1.2% of the larger side; set
  `outline_width` for the old 1%.
- **Brands with several logos add only the logos marked `auto: true`**, and unknown logo fields are an error.
- **Proportional templates scale numbers that variables and `=` expressions produce.**
- **Render lockfiles are version 2.** Earlier releases cannot read them; version 1 lockfiles still verify.
- **Noto Sans is the proofing face.** Text with no font draws in Noto Sans instead of DejaVu Sans, so default
  renders and text widths change; DejaVu Sans stays bundled as a fallback. Name `DejaVuSans.ttf` on a layer, or
  register it as the body font with `font-register {name, asset: "DejaVuSans.ttf", role: body}`, to keep it.
- **Saved characters live in the object library.** `character-save` writes `object_library`; run `vixl convert` on
  a document with an old `character_library` to move its entries (the engine still reads them). `character-cycle`
  refuses walk, run, ride or wave on a rig without the bones the cycle moves.
- **`layer-intent` `tags: ["optional"]` becomes `priority: optional`**, and a stack's `align: "middle"` becomes
  `center`; both are reported under `normalized`.

### Typography and components

- **Small caps.** `text_transform: "small-caps"` on `text` and `text-set` draws lowercase letters as small capitals
  without changing the stored text: the font's own small capitals when it has the OpenType `smcp` feature, else
  capitals at 0.7 of the size with 5% added tracking. A rich-text span takes `small_caps` (Markdown
  `[words]{small-caps}`, `text-style` `small_caps`, CLI `--small-caps`). The glyphs come from the shared shaper, so PNG,
  SVG and PDF draw the same ones, and PPTX writes the run with `cap="small"`. `font_variant` and `smallcaps` are
  accepted and reported under `normalized` (#652).
- **Hanging punctuation.** `hanging_punctuation: true` on `text`, `text-set` and `rich-text` sets opening quotes,
  brackets and bullets outside the start of left-aligned lines, and closing quotes, stops and commas outside the end of
  right-aligned ones (both in centred lines), so the letters line up with the edge. A hung mark needs no room in a text
  box (wrapping and `fit-text` measure the letters between the edges), auto-sized text gets a box that starts at the
  first letter, and the bounds and safe-area checks count the marks. PPTX writes `hangingPunct` and hangs the first
  line with a negative indent. It is opt-in: turned on for headings, the house-style eval's share of designs without a
  composition finding fell from 1.0 to 0.979 at every variety level, so no default sets it (#652).
- **Accent words on any text.** `text` and `text-set` take `accent_words`, as `layout-apply` does: whole words, matched
  without regard to case, become `@accent-text` spans, and words not found are listed in the warnings. Rich-text
  Markdown has the flags `[Winter]{accent}` (`@accent-text`) and `[Sale]{accent-bg}` (`@on-accent` on an `@accent`
  highlight). These name palette roles; a document without them is refused with the remedy instead of failing on an
  unknown swatch (#650).
- **Highlighted rich text is measured against its highlight.** The contrast check compared the glyphs of a highlighted
  span (`==marked==`, `highlight=`, `accent-bg`) with what lies under the layer instead of with the highlight they sit
  on, so light words on a dark highlight failed and dark words on a dark highlight could pass. It now reads them against
  the highlight, for top-level and grouped text (#650).
- **Callout, band and labelled-rule containers.** `callout` is a title and body on a panel tinted toward the accent,
  with an accent rule and an optional icon; `band` a header or footer strip with text and an optional detail; and
  `labelled-rule` a label between two rules. They use palette roles, hide their optional parts when empty and are not
  picked by rolls, so rolled documents are unchanged (#650).
- **Font pairs bring the body italic.** `font pair`, and `font install` with the body role, also install the italic of a
  body face that is a catalog text face with one (registered as `family-weight-italic`), so italic rich text draws the
  real italic instead of a slanted roman. When it cannot be fetched the install still succeeds and `body_italic.skipped`
  says why. Rolls and new documents install two styles as before; optical sizes (`opsz`) are not used (#652).

### Craft checks and variations

- **Four hierarchy findings join the composition check (breaking).** `flat_hierarchy` (two or more text blocks whose
  largest text is under 1.6 times the body size), `single_weight` (three or more text blocks in one face and one
  weight), `no_focal` (the two heaviest blocks of a page of type and pictures weigh within 15% of each other) and
  `accent_unused` (a page built on the document's palette never draws the accent its direction rolled) are `review`
  findings like the spacing codes: a plain `check` passes with them, the `final` profile fails until they are fixed or
  waived with a reason, and `repair-layout` applies nothing for them (which line leads is a judgement call) and lists
  `suggestions` under `reviews_remaining`. A document that passed `final` before can now fail it; the thresholds are in
  `composition.THRESHOLDS`. On the craft backtest none of them adds a false finding, but no judged defect of the
  reconstructions is of these kinds, so what they catch is not measured there; the 144 rolled designs of the
  house-style eval still have no composition finding. Documented under [composition](docs/guides/layout/guides.md#composition). (#649)
- **`variations` compares seeded rolls of the open document.** `vixl_apply(workflow='variations', request={output, count
  or seeds, locks, slots})` renders 2 to 4 rolls on copies, writes one labelled contact sheet (the MCP tool also returns
  it as an image) and gives each tile its seed, layout, palette, finding counts and the `roll` step that makes it real.
  The open document is unchanged until you apply the chosen step. The `roll` step takes `replace` to re-roll a document
  that already has a layout instead of failing on the name clash. See [safe variety](docs/guides/layout/safe-variety.md#comparing-variations). (#649)
- **Finishing pairs for agents.** `skills/vixl/references/finishing-pairs.md` describes six generic pages and their
  finished versions in words, each with the exact operations that close the gap (a flat type scale, one weight, two
  rival headlines, an unused accent, a dead band, two left margins); a test applies every pair and checks that the
  finding appears and then disappears. The `finishing` checklist now asks for steps in the type and for the accent to be
  used, and points at `variations` when the composition itself is generic. (#649)

### Palette and decoration from the brief

- **Rolls draw one, two, three or no accent colours (breaking).** A roll's direction now carries `accent_count` and
  `accent_representation`: one accent in 55% of rolls, two in 30%, none or three in 7.5% each (a mark rolls one,
  sometimes none or two), shared `equal`ly or `skewed` toward the first (70/30, 60/25/15). Both come from a separate
  stream of the seed, so a seed keeps its palette, layout and first accent; a seed that now rolls two accents draws
  some of its rules, dots, labels or margin motif in the second, and one that rolls none draws its accent shapes in
  the ink colour and accent text in the muted one. A shape carrying text (the call to action, a highlighted date)
  keeps the first accent. A layout with fewer places for an accent than the roll asks for adds the margin motif
  where a corner is clear of the text, then leaves the rest out; the layout record's `accents` lists the accents
  `drawn` and says why any is missing. `accent_unused` checks every drawn accent and skips a direction with none,
  and charts with several series start from the drawn accents. Restore one accent with `locks={accents: 1}`
  (`--lock accents=1`), or roll nothing with `house_style: "off"`. On the house-style eval every quality share stays
  1.0 at every level and 19 of the 20 two- and three-accent rolls per level draw all their accents (the third finds
  no place in the other); the diversity mean and image and structure distances are unchanged and the same-mode
  distance moves from 0.1022 to 0.1020 at low (one poster's corner block turning from green to purple), 0.1394 to
  0.1395 at medium and stays 0.166 at high, all above the stored baseline. See
  [safe variety](docs/guides/layout/safe-variety.md#accent-colours). (#404)
- **`@accent-2` and `@accent-3` palette roles.** Two or three accents add these roles with `-text` variants: the
  palette's next most colourful entry at least 30° of OKLCH hue from the accents before it, else the first accent
  turned in hue at the same lightness and chroma, nudged to 3:1 as a fill and 4.5:1 for text, each with its reason in
  `layout.roles`. Only the accents a layout draws get swatches. Colours you fix (`colors`, a brand palette) get no
  invented accent; a brand palette may set `accent-2` and `accent-3` (and their `-text` roles). On `layout-apply` the
  count goes in `direction`: `{"accent_count": 2, "accent_representation": "equal"}`. (#404)
- **A brief's words weight the rolled palette (breaking).** Motif themes carry `moods` (coffee is warm, cozy,
  earthy, rustic and crafted) and the house style a keyword table (`taste.moods.keywords`: `cozy` and `autumn` are
  warm, `luxury` luxurious, `quarterly` corporate). The roll attached to `vixl_reference(brief)` weights palettes
  with one of the brief's moods three times within the rolled tier, so a coffee brief picks warm or earthy palettes
  about 45% of the time instead of 27% while still seeing nearly every palette. The direction reports
  `mood_source: "brief"`, `brief_moods` and `mood_words`, and the best theme's first element as
  `motif_suggestion` (what to draw; no layers are added). A brief with no matching word rolls exactly as before.
  Choose the palette yourself with `locks={palette: NAME}`, or roll nothing with `house_style: "off"`. See
  [safe variety](docs/guides/layout/safe-variety.md#moods-from-the-brief). (#654)
- **The house-style eval counts accents.** It reports the accent count rolled as a diversity dimension and, as a
  quality share, how many two- and three-accent rolls draw all their accents (`accents_drawn`, now in the baseline).
  (#404)

### Layout and adaptation

- **Stacks speak CSS flexbox and grid.** `justify` also takes `space-between`, `space-around` and `space-evenly`;
  `align: "stretch"` sizes members across the box (text wraps to its width, shapes, solids, gradients and frames fill
  it); `grow: {member: weight}` shares the free space along the stack (`stack_grow` on the member); a horizontal stack
  with `wrap: true` continues on new rows `row_gap` apart; and `direction: "grid"` places members row by row in
  `columns` (a count, or widths such as `["1fr", "2fr"]` or `[240, "1fr"]`) with `span: {member: n}` (`stack_span`),
  wrapping text that is wider than its cell. Grid columns use the same column math as `grid` guides. Stretched and
  grown sizes exist only while the document is laid out, so every renderer and exporter draws them and `remove: true`
  writes them into the members. The CSS spellings (`justify_content`, `align_items`, `flex_direction: "row"`,
  `flex_wrap`, `flex_grow`, `grid_template_columns`, `flex-start`) are accepted and reported under `normalized`, the
  CLI has `--wrap`, `--columns 1fr,2fr`, `--row-gap`, `--grow NAME=W` and `--span NAME=N`, and a `stacks` guidance
  entry maps the CSS model for agents (#653).
- **`adapt-layout` rebuilds an unedited layout at the new size by default (breaking).** A document built by
  `layout-apply` and not edited since is now recomposed from its stored recipe, as `recompose: true` did before, so a
  post becomes a story or banner composed for that format instead of a scaled copy. The layout record keeps a
  fingerprint of the layers it made (layer IDs do not count); any later edit, a layer the layout did not make, or a
  proportional option (`anchors`, `where`, `scale`, `text`, `together`) keeps the anchoring rules. Every report and
  every `adapt-sizes` copy says `recomposed` and a `reason`; `recompose: false` (CLI `--no-recompose`) restores the old
  default (#653).
- **Arrangements re-place any document and keep the best one.** `adapt-layout` `arrangements` (`stack-vertical`,
  `side-by-side`, `hero-top`, `proportional`) builds each candidate, scores it with the composition, legibility,
  bounds and overlap checks and keeps the one with the fewest unmet requirements, fix findings and review findings.
  Copy is re-wrapped to its column with balanced lines and shrunk no further than `min_text` (raised to the size the
  legibility check asks of social and poster pieces). The report lists `candidates` and carries an `outcome`
  (`outcomes.make`): validated when the kept candidate passed, `needs_review` when none did (#519).
- **Priorities, focal points and required copy.** `layer-intent` takes `priority` (`required`, the default,
  `optional` or `decorative`) and, on image and frame layers, `focal: [x, y]`. Optional and decorative layers are
  hidden when they would be too small to read or an arrangement has no room; required copy is never hidden or cut off
  (its text box grows to its lines) and copy that still does not fit is listed under `requirements` and fails the
  arrangement's validation. A cover crop centres the focal point as far as the image allows and is reported under
  `crops` with the pixels lost on each side. The `optional` tag is an alias for `priority: optional` (#519).
- **Each adapted copy runs the document's suites.** `adapt_copies` and `vixl_apply(workflow='adapt-sizes')` run the
  document's attached check suites on every copy and attach each copy's `suites` results and `outcome` (`suites`: true
  by default, a name or list, or false; CLI `--no-suites`); `options` also accepts `arrangements`. A `pytest -m perf`
  budget covers adapting a poster to three sizes with four arrangements each (#519).

### Atmosphere and motifs

- **Fog for `haze`.** `haze` takes `form: "fog"`: two to five stacked soft horizontal bands (`layers`, default 3) that are
  lighter, less saturated and denser toward the horizon, with the nearer bands taller. `density` sets how thick the fog is,
  `seed` where the bands drift, `color` the nearest band's colour (default a pale blue-grey), and `target` or `x`, `y`,
  `width`, `height` the zone. `behind` names the foreground layers the fog sits behind, so they stay crisp (default: below
  the lowest text layer); run it once per gap for mist between ranges of hills. It is an editable group of gaussian
  gradients, vector in every export, like the other atmosphere operations. `layers`, `density` and `behind` are refused on
  the `band` and `round` forms instead of being ignored (#655).
- **The atmosphere decision is recorded, with golden coverage.** The [atmosphere guide](docs/guides/finishing/atmosphere.md)
  says why reflection, haze, star-field, string-lights and bokeh are operations that write editable layers and not stack
  effects (an effect has no parts to edit and every exporter would have to learn to draw it), and that light falloff is the
  `lighting` operation. A new visual fixture, `atmosphere_scene`, draws stars, a haze glow, fog behind the near hill, string
  lights, bokeh and a reflection on one small canvas (#655).
- **Five motif shapes.** Catalog shapes `microphone` (grille slots, cradle, stem, base), `snowflake` (six arms with two pairs
  of branches, one merged outline; `thickness` sets the arm width), `leaf` (stem, midrib and veins), `book` (open, with
  lines of text and the cover showing) and `balloon` (highlight, knot and wavy string) draw what composed shapes drew
  badly. Each is one editable outline of plain curves with cut-outs wound against the body, so SVG, PDF, PowerPoint and the
  preview flatten it with the same Bezier evaluator, and each reads at 24 px as well as at poster size. The visual fixture
  `catalog_motif_shapes` shows them at both sizes (#651).
- **Nine more motif themes, and three questions.** `vixl_reference(brief)` now also returns motifs for bakeries, gardens
  and botanicals, winter and the holiday season, sport, tech and product launches, wellness, travel, books and reading,
  and kids' parties (16 themes in all). `bakery` moved from the coffee theme's keywords to its own theme. Every theme
  answers what the object is, what it emits or reflects and what frames it, and the `motifs` guidance now asks those three
  questions before drawing. The music theme draws a stand microphone with the new `microphone` shape, and the coast and
  lake themes draw morning fog and mist with `haze` `form: "fog"` (#651).

### Illustration defaults

- **New organic forms and `object-plan` scaffolds are drawn flat vector in a document with a house style (#427,
  breaking).** The decision (house style F5) is data, `craft.illustration` in `house-style.json`, read through
  `house_style.illustration()` and applied by `craft.illustration_style(project, box, rng)`: ink part lines (outline
  policy `parts`) 1.2% of the object's larger side, a hard offset `drop-shadow` (blur 0, ink, 35% opacity, 3% of the
  larger side toward the bottom right, as the light is at the top left), a `subtle` `irregular` wobble and, on about
  15% of forms (the seed decides), one or two thin extra lines inside the outline. In `organic`, every filled part
  gets the ink line (a part of small elements a finer one, so seeds and spots are not drowned, and those parts are not
  wobbled), the form gets the shadow, and the extra lines are generated `NAME/outline-1` layers; forms with no filled
  part (a fern) and the presets that cover a surface (`spots`, `scales`, `cells`, `giraffe`, `water`) are unchanged,
  and a `stroke`, `stroke_width`, `fill` or `colors` you give wins. In `object-plan`, the batch ends with the
  wobble, an `object` `action: outline` with policy `parts` (parts too small for the line, such as a person's eyes,
  get `outline: none`), `outline_lines` now and then and one `drop-shadow` on the object (a sub-object is outlined and
  leaves the shadow to its object); the `figure-plan` output is byte-for-byte unchanged. A bare `Project(width,
  height)` and a document made with `house_style: off` have no house style and draw as before. **Restore the old
  look** per form with `illustration: "plain"` (or `outline: false`, reported under `normalized`; CLI `vixl organic
  PRESET --illustration plain`), for a document by creating it with `house_style: off`, or on a made form with
  `layer-style` `remove: true` for the shadow and `irregular` `remove: true` for the wobble. The house-style eval (`python -m evals.house_style --compare`) is
  unchanged at every variety level: its sparse-brief designs draw no organic forms. See
  [organic](docs/guides/shapes/organic.md#house-illustration-finish) and
  [object-plan](docs/guides/shapes/objects.md#scaffold-with-object-plan).
- **Double and triple lines on objects: `outline_lines` (#427).** `{type: object, action: outline, outline_lines:
  [{gap, width}]}` draws up to three thin lines inside the outline, parallel to it, as generated `NAME/outline-N`
  layers that are redrawn with the outline when a part moves and go with `outline-remove`. `outline_width` now
  defaults to 1.2% of the larger side under `outline: parts` (the house part line; `silhouette` keeps 1%) (breaking:
  restore with `outline_width`). See [outline policy](docs/guides/shapes/objects.md#outline-policy).

### Fonts

- **Noto Sans is the proofing face (breaking) (#419).** Text without a font (and roles the document's typography does
  not set) is drawn in the bundled `NotoSans-Regular.ttf` instead of DejaVu Sans, so every default render changes:
  Noto Sans is narrower, with taller line metrics and deeper descenders. DejaVu Sans stays bundled and nameable, now
  after Noto Sans in the fallback order (it draws the Arabic, Hebrew, Armenian and Georgian that Noto Sans lacks), and
  layers that name `DejaVuSans.ttf`, as text saved without a chosen font before this release does, keep drawing it. Restore it
  for new text with `"font": "DejaVuSans.ttf"` on the layer, or as a role's face with
  `{type: font-register, name: dejavu, asset: DejaVuSans.ttf, role: body}` (`font-register` now embeds a bundled face
  named as its `asset`); `font-fallbacks` accepts either bundled face. The `fonts` check reports text in either
  bundled face as the proofing fallback. The conversion kit's `preserve` look writes `DejaVuSans.ttf` into chart,
  table, key-value and diagram recipes that name no face (`proofing-font`, documents before 0.27); later documents'
  recipes redraw in Noto Sans on their next edit. A missing font in an SVG import falls back to Noto Sans.
- **CJK, Devanagari and Thai draw from a face already on the machine (#419).** When no document font covers such a
  character, the fallback chain adds the matching catalog Noto face from the font cache (left by `font-cover` or
  `font install`; any cached CJK face serves Han) or from `VIXL_CJK_PACK` (a font file, or a zip of files named like
  the font cache), without the document registering it and without any download while rendering. Exports draw it
  like any fallback face (PDF embeds the subset it draws). Because the document does not embed it, the apply warns and
  `check` reports a `fonts` warning naming the step that does; `font-cover` without arguments now embeds such faces
  too. With no face on the machine, the apply warning and the `fonts` error name the exact step and command, such as
  `{"type": "font-cover", "scripts": ["Han"]}` and `vixl font cover --script Han`. `vixl.packs` has the seam for a
  pinned `cjk` content pack (`vixl.packs.local`, documented in [plugins](docs/reference/plugins.md)); none is
  published yet.
- **Layout and export fixes the new face brought out.** Logo taglines and a banner's call to action are measured in
  the face they are drawn in, not the proofing face. A wide banner too shallow for a call to action under the copy
  beside the headline (a LinkedIn cover with a two-line subtitle) puts the button in a third column instead of past
  the bottom edge. The event poster grows its type while its facts would otherwise be moved to the foot past an empty
  band, so a pixel either side of 60% fill no longer decides. A diagram given a box no longer ends up to 1.5% larger
  than it. A boxed text whose first glyph starts left of its origin (the tail of J) is reported as cut off only when
  its ink leaves the box. PDF exports set letter spacing as character spacing (`Tc`), so extracted tracked text no
  longer reads as spaced letters. SVG raster imports draw text that names Noto Sans as well as DejaVu Sans.

### Objects

- **Kinds say how to build one (#376).** Every object kind has a `build` block, merged down the taxonomy: the
  approach, workflows, operations, organic presets, shapes, patterns, looks, palette, placements (where each part
  goes, such as `{part: leg, anchor: body.bottom, at: top, spread: "0.15-0.85"}`, with the anchor names of `align`),
  guidance, short offline research notes, checks and a working example batch. The organic, constructed, natural and
  symbolic domains and their classes carry general blocks; person, dog, cat, bird, fish, tree, flower, leaf,
  mushroom, guitar, car, house, cup, rock and cloud have their own, each with an example that passes the object
  check. `vixl_reference("guitar")`, `vixl_reference('objects', name=…)`, `vixl objects show` and the object summary
  of a brief return it, declaring an object adds a `next_steps` entry that points to it, and a workspace kind may
  add its own (the names it uses must exist). See [objects](docs/guides/shapes/objects.md#the-build-block).
- **The `object` check (#378).** `vixl_check` measures every declared object and sub-object against its kind:
  required parts missing or miscounted (a dog with three legs), paired parts without a side, unknown part names,
  gaps between parts that must touch (on the drawn ink, and at the poster, middle and last frames of a timeline:
  `guitar/neck ↔ guitar/body: 6 px gap`), proportions outside the kind's range, mirrored pairs that differ in size
  or sit on one side, and parts stacked against the kind's layering. Findings carry `rule` (`object.part-count`,
  `object.gap` …), `layer_ids`, `box`, `measured`, `action` and a `hint` that names the build placement. New
  `object` fields: `stylized: true` and `proportions: "ignore"` silence the proportion findings, and a part's
  `depth: far|near` marks side-view limbs. Each part is drawn once per frame on a tile the size of its object, and
  `tests/test_perf.py` holds a budget for it. See [the object check](docs/guides/shapes/objects.md#the-object-check).
- **`object` runs by default on pages with declared objects, and `connected` leaves them to it (breaking).** A
  plain `vixl_check` of a document with a declared object now reports `object` findings; missing parts and gaps
  are `fix` findings, so `passed` can turn false where it was true. When both checks run, a gap in a declared object
  is reported once, by `object`. Pages without declared objects, and standard characters without an object record
  of their own (still the `character` check's), report as before.
- **Outline policy per object and part (#379).** `{type: object, action: outline, target: dog}` applies an outline
  policy stored on the object record: `outline: silhouette` writes one `NAME/outline` path layer, the object's top
  child marked `generated: {by: object-outline}`, around the union of what its layers fill, and sets the part strokes
  by `interior` (`hide`, `thin` at 40% of the width, or `show`); `parts` outlines every part alike; `none` puts the
  original part strokes back, as does `action: outline-remove`; `inherit` (the default) is the kind's policy from the
  taxonomy (organic and constructed kinds silhouette with thin interior lines, natural none). `outline_color` and
  `outline_width` set the line; a part takes its own `outline` (`none` keeps its stroke, `parts` gives it a full
  contour) and `interior`. Open and unfilled shapes keep their strokes and add no area. When an apply moves, resizes
  or adds a part, the outline is redrawn in the same undo step. The object check reports `object.outline-seam`,
  `object.outline-weight` and `object.outline-stale`, the outline is the same unfilled stroke in PNG, SVG, PDF and
  PowerPoint, and `duplicate` carries the stored strokes to the copy. CLI: `vixl object outline GROUP [--outline
  parts]`, `vixl object outline-remove GROUP`. See [outline policy](docs/guides/shapes/objects.md#outline-policy).
- **`object-plan` scaffolds an object from its kind (#380).** The new workflow (`vixl_apply(workflow='object-plan',
  request={kind, height, apply})`, CLI `vixl object plan KIND --height N [--apply]`) writes a placeholder per part
  from the kind's build block: shapes, sizes and colours from its example, positions from its placements, proportions
  at the middle of their range (`seed` varies them inside it), back to front with sides and depths, each part pushed
  into a 2 px overlap with what it attaches to, then `group`, `object` and the part names. Every seed kind's scaffold,
  and every other kind that lists parts, passes the object check as generated. `box` or `x`/`y`/`height` place it
  (by default it fits the canvas), `with: ["guitar"]` nests sub-objects, and a person comes from head units
  (`head_units`, `width_ratio`) with all 17 standard parts. `apply: false` (the default) returns the batch with a
  next step per part and changes nothing; `apply: true` is one undo step. Every domain's build block now lists it
  under `workflows`. See [object-plan](docs/guides/shapes/objects.md#scaffold-with-object-plan).
- **`figure-plan` is object-plan's person template.** `figure-plan` now runs `object-plan` with `kind: person` and
  `template: figure-plan`; its operations, parts map, head units and next steps are byte-for-byte what it returned
  before, and the result adds a `normalized` entry naming the workflow it ran. The person kind's build block lists
  `object-plan` instead of `figure-plan` under `workflows`.

### Brand packages

- **Multi-logo brands no longer add every logo to every document (breaking).** A brand.json logo takes `purpose`
  (`icon`, `wordmark`, `avatar`, `lockup`), `place` (`anchor`, `margin`, `width_fraction`, `safe`) and `auto`. Layouts,
  templates and `brand-preset` add only automatic logos; `auto` defaults to true for a brand with one logo and false
  when it has several, so give the one that should appear everywhere `"auto": true`. A logo with `place` sits at its
  anchor, `margin` from the edge and inside the safe area; without `place` it keeps its `x`/`y`/`width`/`height` as
  before. Unknown logo fields are now an error (#436).
- **`brand-logo` places a brand logo by purpose.** `{"type": "brand-logo", "purpose": "wordmark", "anchor": "bottom"}`
  places the first logo of that purpose (moving an existing layer of that name rather than adding a second), and the
  logo rules (clear space, minimum size) count it. A template that places its own logo sets `"places_logo": true`, so
  applying it adds no automatic logo (#436).
- **Brand elements.** brand.json `elements` holds multi-part objects (the record `object-save` keeps, with the files
  its layers use embedded), placed with `object-place` as `brand:NAME` before the document library is looked at.
  `vixl brand element NAME --from FILE.vixl [--object GROUP]` saves one from a document (#436).
- **Custom brand styles.** brand.json `styles` defines styles with guidance, rules of the catalog's rule kinds and
  recommended looks. Documents tag one with `style-set` as `brand:NAME`, and `check --checks style` enforces its rules
  while that brand is active (#436).
- **`vixl brand init`, `pack` and `install`.** `init` writes a valid brand.json from a palette, a pairing and embedded
  `--font ROLE=FILE` fonts. `pack OUT.vixlbrand` writes the brand and the workspace resource library (palettes,
  templates, workflows, suites, guidance, assets …) as one deterministic ZIP with a SHA-256 manifest. `install`
  validates the whole package first, then writes brand.json, the library and the asset files atomically and rolls back
  on any failure; it never runs code, and `--preset-only` adds the package's brand as a preset instead (#436).
- **`brand validate` checks more.** It also decodes element files, flags hex colours in brand style guidance that the
  palette does not approve, and flags workspace templates that set a font role the brand does not define (#436).
- **Packs can carry images.** A new `assets` resource kind, `{data_base64, media_type: png|jpeg|svg|webp, credit,
  license}`, installs from plugin packs, brand packages and `resource-save`. Saving checks the base64, the file
  signature, at most 2 MiB per asset and 20 MiB per plugin pack, a still image within the document limits, and SVG
  through the static-SVG import rules. The bytes are stored by SHA-256 beside the resource library
  (`.vixl-resources-assets/`), so the library file stays small (#530).
- **`asset-place` places a pack image.** `{"type": "asset-place", "resource": "acme-badge", "x": "center", "y": 40,
  "width": 200, "anchor": "top"}` embeds the asset once however often it is placed, renders SVG at the placed size,
  and records `{resource, sha256}` (and credit and licence) in the layer's provenance. Templates may use it, and it
  scales with `proportional`. A placed asset satisfies a brand `required_elements` entry or a `group-check` required
  layer named after its resource (#530).
- **Constraints read text line metrics.** `REF.line[N].start` and `REF.line[N].end` (where a line's pen starts and
  ends; `-1` counts from the end) and `REF.baseline[N]` follow the copy as the renderer sets it, with offsets in pixels
  or `em` of that text's size: `{"left": "lyric.line[-1].end+0.25em", "bottom": "lyric.baseline[-1]"}` keeps a mark
  after the last word of a variable lyric. Line refs are checked for the right axis and an existing line (#529).
- **Arithmetic in templates and workflows.** A template, container or workflow field whose whole value starts with
  `=` is evaluated after its variables are filled (`"x": "=${pad} + 76.34 * ${k}"`) and reported under `normalized`;
  `==` writes a literal `=`. A safe evaluator allows numbers, `+ - * / // %`, parentheses, `min`, `max`, `round` and
  `abs`; names, attributes, other calls and `**` are refused, length and size are bounded, and division by zero is
  an error. The `calc` variable filter does the same inside text: `${price|calc:x*0.8|number:2}` (#529).
- **Proportional templates scale numbers from variables (breaking).** Variables and `=` expressions are now filled
  before a `proportional` template scales, so a size or position a variable gives scales like a written one (#529).

### Merch

- **Merch products for the `mockup` workflow.** `tee`, `long-sleeve`, `crewneck` and `hoodie` (flat lays, front and back in
  one scene), `tote`, `sticker` (die-cut), `sticker-kiss-cut`, `enamel-pin`, `patch`, `button`, `cap`, `beanie` and `socks`
  join the phone, laptop, browser, poster, business card and mug. They are drawn as vector paths from measurements in the
  `brand_kit` plugin (`products.py`, `garments.py`, `goods.py`, `accessories.py`; about 300 KB of generated path data, no
  pictures), with seams, stitching, ribbing and folds as multiply and screen layers over the base layers, so one drawing
  reads on white and on black. Wave 2 of the plan (crewneck, cap, beanie, socks, patch, button) is included. The core is
  unchanged (#444).
- **Named print areas on templates.** A template has `areas: {name: {corners, print_size_mm, clip_path?, surface?, finish?,
  cut?}}` besides its `slots`; the garments carry `front-chest`, `full-front`, `back`, `sleeve-l` (the wearer's left),
  `sleeve-r`, `hem-tag` and `inside-neck`, and every area keeps the aspect ratio of its print size. `mockup-save` takes
  `areas`, `base`, `garment_color` and `main` (the placements a bare `design` fills) too, and `mockup-list` shows each
  template's areas, print sizes and default colour.
  `poster-wall`'s slot is now A3-proportioned (297 × 420 mm) and carries a print size (#444).
- **`place: {area: design}` on `mockup`.** Each design is clipped to its area's path and fitted by `fit`; an entry can be
  `{design, fit, finish, source_page, artboard}`. A bare `design` fills the slots, or the main area of a template that has
  only areas, and `design` is no longer required when `place` is given. An unknown area lists the template's areas. The
  mockup record keeps `placed` and `areas` (#444).
- **`garment_color` recolours only the base layers.** The garment, bag or cap is drawn as base layers (`base`) under
  shading layers, so a colour request changes the fill of those layers and of the area surfaces under the prints and
  nothing else; a template without a garment colour refuses the field (#444).
- **Print finishes.** `finish: screen | puff | embroidery | enamel | woven` (or `none`) puts an ordinary stack on the placed
  design: effects and layer styles plus helper layers (dot screen, thread hatch, satin sheen, weave, gloss) clipped to the
  design's shape, per request or per area. The pin and the patch default to `enamel` and `embroidery`. They are mockup
  finishes in the plugin, not new `look` presets; the core `look` list is unchanged (#444).
- **Stickers, pins and patches follow the artwork.** After the design is placed, `die-cut` traces its ink and the cut shape
  goes under it: a white vinyl border (die-cut), a thin cut line on the backing sheet (kiss-cut), a gold rim (pin) or a
  dashed merrow border (patch), each with a soft shadow. Area `cut: {mode, border_mm?, color?}` does this in a template (#444).
- **`print-art` action: print-ready files per placed area.** Each area is written at `print_size_mm` × `dpi` (default 300) as
  `AREA.png` with its resolution and transparency, plus an editable `source/AREA.vixl`, through the export path (call
  limits, no overwrite without `overwrite: true`, a failure removes what it wrote). `spot_colors: N` posterizes to at most N
  flat inks (perceptual merge in OKLab) with `AREA-spot.png` and one film positive per ink as PNG, or as PDF pages with
  `separations: "pdf"`; `underbase: true` adds a white choke layer (`choke_mm`) for dark garments only (relative
  luminance under 0.4), and says why when it skips a light garment or a product that is not a garment (#444).
- **Templates can use pack images.** `asset-place` is allowed in a template's `operations` and `overlay`, so a custom
  product photo or label can ship in a pack; a missing resource fails the mockup with `missing_asset` (#444, #530).

### Characters

- **One library for saved characters and objects (breaking).** `character-save` now writes the document's object
  library (`object_library`, the records `object-save` keeps, kind `person` or the character's own object kind) and
  `character-load` reads it, so `object-place` places a saved character too; `character-load source=` imports into
  the same library. The separate `character_library` is no longer written. A document that still holds one opens as
  before and `character-load` reads its entries; `vixl convert OLD.vixl` moves them into the object library (rule
  `character-library`, run on documents from every release, a taken name getting a `-character` suffix). Code that
  read `state["character_library"]` reads `state["object_library"]` (#521).
- **Portable character packages (`.vixlchar`).** The `character-package` workflow action writes a rigged character
  as one deterministic ZIP: its portable character document and a versioned manifest with the name, kind, the
  character's own `version`, parts, rig, named expressions (`{name: {part: variant}}` over eyes, brows and mouth),
  poses (`{name: {joint: degrees}}`), motions (a `character-cycle` or pose keys), the checks to run on each copy, and
  the fonts and images it uses, every file with a SHA-256. Left out, expressions, poses and motions default to the
  built-in ones the character can use (`confused`, `celebrate`, `wave`, `walk` …). Output is never replaced without
  `overwrite: true` (#521).
- **Discover, inspect and place packages.** `character-discover` lists the packages in the workspace and in the user
  library (`VIXL_CHARACTERS`, else `~/.config/vixl/characters`) and the characters saved in the open document;
  `character-inspect` verifies one and returns its manifest; `character-place {package, pose?, expression?,
  motion?}` places an editable copy with new IDs and its rig bindings, in one undo step, and reports the package's
  checks on it. `colors` and `outfit` recolour a copy; `scale`, `width` or `height` scale it whole, and only
  `scale_parts` changes proportions (#521).
- **Located character errors; a cycle needs its bones (breaking).** A joint the rig does not have (`pose.left-elbow`,
  suggesting `left-lower-arm`), a motion whose cycle needs bones the rig lacks and an expression on a missing part are
  errors with the field, the character and what it has, on place and in `character-pose`, `character-cycle` and
  `character-package`. `character-cycle` now refuses `walk`, `run` and `ride` on a rig without `left-upper-leg` and
  `right-upper-leg`, and `wave` without `right-upper-arm` and `right-lower-arm`, naming the cycles the rig can drive;
  before, such a cycle quietly left the missing limbs out. A package is read within fixed bounds (64 MiB, exactly
  two members, no encryption), checked against its manifest before anything changes, and never executed (#521).

### Reproducibility and delivery

- **Render lockfiles cover every page, artboard and frame.** `vixl reproduce --write-lock` writes a version 2 lockfile
  (version 1 files still verify) with the render hash of each page and artboard and of sampled timeline frames
  (`--frames N` or `--times 0 1.5s 50%`; an animated document gets three by default), a hash of the variable set or
  campaign rows with one per variable name, and every `seed` in the document. `--lock` locates a change: `page 2`, an
  artboard by name, a frame by time, a variable or seed by name. The lockfile version 2 is not readable by earlier
  releases (#512).
- **Lockfiles record exports.** `--write-lock FILE --export png "jpg:quality=80" mp4:fps=24` encodes each export in memory
  and records its options (defaults filled in), the SHA-256 of its bytes, the SHA-256 of its decoded pixels or sampled
  frames, a coarse 16x16 block-average signature, and the ffmpeg version or ICC profile hash it used. `--lock FILE
  --export` encodes them again and reports `byte_identical` and `visually_equivalent` per export, separately: bytes decide
  PNG, SVG, PDF, HTML, PPTX, PSD, TIFF and APNG, decoded pixels or frames within `--export-tolerance` decide JPEG, WebP,
  AVIF, GIF, MP4 and WebM, and `--export-visual` judges every format by its pixels. A requested export that differs from
  the locked one is `export-setting` drift (`jpg.quality`), a changed ffmpeg or ICC profile `toolchain` drift
  (`mp4.ffmpeg`, `pdf.icc_profile`), and a recorded export that alone differs gives the new `export-mismatch` level.
  The workflow takes `exports`, `verify_exports`, `frames`, `times`, `export_tolerance` and `export_visual` (#512).
- **A manifest-ready reproduction summary.** `reproduce(..., report=True)`, `--report` and `report: true` return a compact
  record (level, the lock's version and SHA-256, drift counts and the first located items, per-export results) instead of
  the full result, for embedding in a delivery manifest (#512).
- **No credential can enter a lockfile.** Writing a lock or a report refuses any value of an environment variable named
  like a key, token, secret or password, or named as a configured AI provider's key variable, and the error names the
  variable, never the value. The [limits of exact reproduction](docs/guides/automation/ci.md#the-limits-of-exact-reproduction)
  (fonts, platform zlib, encoder versions) are now documented (#512).
- **Delivery packages.** The `package` workflow action and `vixl package` write the completed outputs of a campaign run
  (`--production out/production.json`) or exported files (`--files "exports/*.png"`) into one zip: files named from a
  template (`{brand}_{doc}_{artboard}_{w}x{h}.{ext}`, also `{locale}`, `{row}` and `{id}`; a name two files would share
  is refused up front with the list), identical files once, `manifest.json` with each file's source document and
  revision, export settings, check state, SHA-256, dimensions, colour space and the codec, frame rate and duration read
  back from the encoded file, the Vixl version, validation coverage and visual-review status, `SHA256SUMS`, the check
  report (Markdown and JSON) and a proof page. Variants the run held are listed under `held` and left out, as are files
  whose source fails its checks or that the proof page's decisions reject. A render lockfile's reproduction summary can go
  into the manifest. The zip is staged and published atomically, `--dry-run` plans without writing, and an existing
  package is kept unless `--overwrite` (#573).

### Evals

- **A craft grader in the agent eval.** Task checks can be `craft`: the composition checks (spacing, rhythm, crowding and
  the four hierarchy codes) run on the document the agent leaves, every finding counted whether or not it was waived.
  The score is `1 - min(1, findings / max_findings)`; the check passes when no finding has a `forbid` code and the score
  reaches `min_score`, and its detail lists each finding's code, layers and region. Four sparse briefs (an event poster,
  a café menu with tab stops and dot leaders, a report cover, a quote card) have reference solutions that score 1.0, and
  `evals/baseline.json` stores a floor per craft task and for their mean, so a check or default change that lowers what a
  finished page scores fails `python -m evals.run --baseline`. Reports show a craft column. (#656)
- **An optional rubric judge.** `python -m evals.run --judge` renders each craft task's document at delivery size and asks a
  model for 1-5 scores on hierarchy, spacing, type, colour, motif and finish (`--judge-model`, `--judge-endpoint` or
  `VIXL_JUDGE_ENDPOINT` for any Anthropic-compatible server). It is off by default, never used by the Agent eval workflow
  or the tests (they script it), kept out of the baseline, and stores its scores, notes and images beside the run. No
  re-judging has been run with it, so it measures nothing yet. (#656)
- **The craft backtest scores the four hierarchy codes.** None fires on the 20 reconstructed documents, so none adds a
  false finding; `single_weight` and `accent_unused` cannot fire there (proofing font, no rolled direction), which the
  [backtest README](evals/craft_backtest/README.md) says. (#649)

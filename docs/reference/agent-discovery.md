# Efficient agent workflows

Start with `vixl_reference('capabilities', name="animation", fields=true)` for operations, field names, workflows, guidance and gotchas relevant to a task. Topics are text, drawing, shapes, animation, atmosphere ([haze, star fields, string lights, bokeh, reflections](../guides/finishing/atmosphere.md) and motifs), film, layout, color, export, testing, objects (the kind taxonomy, object paths and the review loop), accessibility and charts (contributed by the charts plugin: `chart`, `chart-data`, `table`, `key-value-list`); any other words (`emoji`, `loop`) match operations and workflows by name, singular or plural (`charts` finds `chart`). `vixl capabilities animation` provides the same discovery through the CLI; each `guidance` name it lists is readable with `vixl_reference(NAME)` (CLI `vixl guide NAME`); exact constraints and examples remain in `vixl_reference('operations', name=[...])`.

The capabilities result is bounded: operations are ranked by keyword score (an asked-for name first, then the topic's words in their listed order) and the first five are listed, with `more: N` counting the rest (`limit=N`, or `limit=null` for all); `gotchas` holds only the entries tagged with the matched topics (every entry when no topic is given); `fields=true` also returns `top_operation`, the first operation's brief schema with one example, so one call is enough to write the first batch. `vixl_reference('operations', name=[...], detail="brief")` gives that brief form for any operation (required fields, types, enums, one example; under 1.5 KB each) and a dot path (`name="text-layout.wrap"`) one property's schema; `vixl_reference('workflows')` is a one-line index, and `name=ACTION` (or a list of up to 10) the request fields with only the definitions they reach. Every `vixl_reference` result carries `schema_version`; pass it back as `if_version` to get `{unchanged: true}` when nothing changed ([MCP tool surface](mcp-toolsets.md#detail-on-demand)).

A brief's guide (`vixl_reference("a poster for a jazz night")` or a kind such as `social-card`) names, besides the approach, operations, layouts, looks and styles, the `containers` that suit the kind (placed with `container-place`), and a `create` object (path, the first recommended size, purpose and layout) ready for `vixl_apply(create=…, operations=[…])`, with `create_with` saying how.

All interfaces normalize operation aliases with the same registry and validate against the same operation schema. MCP restricts filesystem access and accepts registered font names and roles. SVG path coordinates are literal local pixels, not percentages or normalized coordinates; `path-fit` fits a path into its layer box. Grouped positions are parent-relative unless `move` uses `space: "canvas"`.

For a new piece with a text frame, `vixl_apply(create={path, purpose or size, layout: {name, …slots}, look, suites: "composition"}, preview=true)` is the first call, not the last: it runs create → font pairing → layout → style → look → operations → check → suites → preview → save → exports in one atomic call; errors carry `step` (see [interfaces](interfaces.md#build-a-piece-in-one-call)). `vixl_reference()` opens with that example; its step-by-step recipe is for edits and for art without a text frame. Keep refining with `vixl_apply`. The finishing pass is sized to the purpose's tier (`finishing_pass` in `vixl_reference(kind)`, from the house-style purpose data): social and quick web (social, slides, diagram, motion) stop once `vixl_check` and the suite pass and the preview reads well; print and brand work (poster, document, form, logo) takes the whole pass. Once the checks pass, `vixl_reference('finishing')` gives it: `vixl_check(checks=["composition"])` (`vixl_apply(workflow='repair-layout')` repairs most of its findings), one fix batch with `check` and `preview` (which returns real-size crops of the two weakest regions), then export. Before handing off, a `proof` workflow page (or `logo-package` for a logo) packages the review; see [production](../guides/automation/production.md#proof-pages).

An atomic batch holds up to 10,000 operations. Generated motion and compact `keyframes` can replace hundreds of handwritten operations. For larger edits use history `begin`, several batches, then `commit`; `rollback` discards the group. A failed batch applies nothing. Explicit `Limits(max_operations=...)` still enforces a lower application limit.

`vixl_check(action='validate')` defaults to a summary with up to 50 failed checks. `verbose=true` includes passes; `targets` accepts layer-name globs, `severity` selects error/warning/info, and `offset`/`limit` paginate. Filters never hide an error from the overall `valid` result. `suppress` explicitly omits named rules or rule globs. Mark intentional bleed with `layer-intent` `allow_crop: true` or a background/decoration role; it then reports informational crop findings.

`vixl_document(action='inspect')` lists 200 layers a page (`offset`/`limit`, `next_offset` null at the end) with `layer_count`. `fields=["bounds"]` keeps only those fields (id, name and type stay), `collapse=true` shows the children of charts, tables, diagrams, containers and object groups as `children: N` at the parent, `filter={type, name (a glob), parent (a layer or "none")}` narrows the list, and `since=HEAD` (the `head` every apply result carries) returns only the layers added or changed since that revision plus `removed`. `vixl_apply(detail='ack')` answers with `{ok, head, changed, warnings}` alone; `dry_run=true` returns a `proposal_id` that `vixl_apply(proposal=ID)` commits while the head is unchanged (`stale_proposal` otherwise); `report_path` on `vixl_check` and `vixl_apply` writes the full JSON into the workspace and returns a bounded summary.

`vixl_render(action='timeline-inspect')` defaults to track names, property names, key counts and time ranges. Use `verbose=true` to include keys, `targets`/`properties` globs and `start`/`end` to narrow the result. Track pagination uses `offset`/`limit`; key pagination uses `key_offset`/`key_limit`. A `next_offset` of null marks the end. Sample a film frame or interval with `film-preview` before rendering the full film; the preview includes film camera framing and transitions.
